# 渐进大纲设计子流程

> Phase 2 执行时的详细操作指南。

## 1. 文档类型判断

根据用户意图和素材内容, 判断属于:
- **技术方案**: 面向客户的解决方案陈述
- **可研报告**: 面向审批的可行性论证
- **解决方案**: 面向投标/销售的综合方案
- **立项报告**: 面向内部审批的项目启动文件
- **其他**: 自定义类型

用户未明确时, 主动提问确认。

## 2. 一级标题设计

### 设计输入
- 文档类型模板 (参考 `references/solution-templates.md`)
- 素材分析结果 (哪些章节有素材支撑)
- 用户指定的引用策略
- 文档目的和受众

### 输出格式

```
建议的一级标题结构:

一、项目背景与目标
  → 理由: 根据PPT中产品概述和行业背景, 需要先建立需求上下文
  → 素材支撑: 产品介绍.pptx (第2-5页), 行业白皮书第1章

二、技术架构设计
  → 理由: 技术白皮书第3章为核心内容, 用户指定借鉴思想
  → 素材支撑: 技术白皮书.docx (第3章)

三、实施方案
  → 理由: 用户未提供素材, 后续需要调研补全
  → 素材支撑: 无 (待调研)

确认后我一次性生成完整大纲。
```

### 设计原则
- 每个标题必须有明确的存在理由
- 标注素材支撑情况 (有/部分/无)
- 逻辑递进: 从Why→What→How→Result

## 3. 全量大纲生成

一级确认后, 一次性输出含二三级的完整大纲:

```
完整大纲:

一、项目背景与目标
  1.1 政策背景与行业趋势
  1.2 建设必要性
  1.3 建设目标与范围
二、技术架构设计
  2.1 总体架构
    (1) 设计原则
    (2) 架构层次
  2.2 核心技术选型
  ...
```

## 4. 大纲编辑

用户可通过以下方式修改:
1. **聊天反馈**: "把2.1和2.2合并", "在第五章后面加一个风险评估"
2. **Web大纲编辑页**: 拖拽排序/重命名/增删

启动 Web 大纲编辑:
```bash
python3 ${SKILL_DIR}/scripts/web_preview/server.py \
  --project <project_dir> \
  --port 5100
```

## 5. 大纲锁定

用户确认后:
1. 保存到 `<project_dir>/02_outline/outline.json`
2. 同时保存 Markdown 版本到 `<project_dir>/02_outline/outline.md`
3. 之后的 Phase 3-6 以此大纲为根结构, 不再修改(除非用户明确要求)
