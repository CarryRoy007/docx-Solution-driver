# 素材分析子流程

> Phase 1 执行时的详细操作指南。由 SKILL.md 主流程调度。

## 1. 接收素材

用户可能提供:
- 单个文件路径 (`/path/to/file.pptx`)
- 目录路径 (`/path/to/materials/`)
- 多个路径混合
- URL

## 2. 运行分析脚本

```bash
python3 ${SKILL_DIR}/scripts/material_analyzer.py \
  --inputs <path1> <path2> ... \
  --output <project_dir>/00_analysis/
```

## 3. 阅读分析报告

读取 `<project_dir>/00_analysis/material_analysis.md` 获取完整摘要。

## 4. 判断素材有效性的标准

- **文本内容**: >20字才有分析价值
- **图片**: 有图题的优先；无图题但从文件名/位置可推断用途的次之
- **幻灯片**: 有演讲者备注的页面更有价值(可能包含写作意图)
- **技术白皮书**: 章节结构清晰, 技术描述规范 → 高价值
- **宣传材料**: 偏营销语言, 信息密度低 → 低价值, 只供参考

## 5. 向用户呈现

以结构化选择题形式呈现, 不使用大段文字:

```
📊 素材分析完成 (N个文件)

核心素材:
  ✅ 技术白皮书.docx (42页, 12张图片)
     → 建议: 借鉴第3章架构设计思想, 摘抄第5章部署方案(去品牌)
     → 图片: 6张有图题, 建议用户指定引用哪些
  ✅ 产品介绍.pptx (15页)
     → 建议: 借鉴产品理念, 不引用具体描述
  ⚠ logo图片 x3 → 不引用(自动过滤)

需确认:
  [ ] 图1-总体架构.jpg → 引用?
  [ ] 图2-数据流.png → 引用?
```

## 6. 素材引用粒度

- **章节级**: 对长文档, 按章节粒度确认
- **段落级**: 对短文, 按具体内容块确认
- **图片级**: 每张图片逐一确认

## 7. 非多模态模型回退

如果模型无法查看图片内容:
- 读取 material_analysis.json 中的 image_captions
- 仅呈现图题和元数据
- 明确告知用户 "当前模型无法直接查看图片内容, 请根据图题描述判断"

## 8. 大型素材策略

素材超过50页时:
1. 提取目录/章节结构
2. 向用户展示章节摘要
3. 让用户标记关注区域(以章节号为标记)
4. 仅对关注区域进行细化分析
5. 其余内容在后续写入中自动忽略
