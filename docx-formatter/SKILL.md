# Skill: docx-formatter

> Word 文档生成与格式化 — 默认格式 / 公文格式双模式。Markdown 入，DOCX 出，确定性脚本保证格式一致。

## 核心原则

AI 不即兴排版。AI 只负责写结构化 Markdown，脚本负责确定性生成和验证 `.docx`。

## 前置确认（BLOCKING）

每次生成前必须确认，等你确认后才构建：

1. 是否使用公文格式（默认普通文档格式）
2. 章节设置
3. 行文逻辑
4. 关键图示（用简单文本展示图示结构）
5. 输出文件名和路径

## 模式选择

**默认：普通文档格式**。仅当用户明确说以下关键词时使用公文格式：
- 公文格式 / 党政机关公文 / 红头文件 / GB/T 9704 / 按公文标准

如果用户没说清楚，主动问："是否需要使用严格公文格式？默认使用普通文档格式。"

## 普通文档格式

### 工作流

```bash
python3 ${SKILL_DIR}/scripts/md_to_normal.py input.md output.docx
python3 ${SKILL_DIR}/scripts/validate_normal.py output.docx
```

### 格式规范

标题层级与编号（脚本自动生成，Markdown 中不需要手动编号）：

| Markdown | 编号 | 字号 | 加粗 | 大纲级别 |
|----------|------|------|------|---------|
| `# 标题` | 文档标题 | 16pt | ✓ | — |
| `## xxx` | 一、 | 16pt | ✓ | L0 |
| `### xxx` | 1.1 | 14pt | ✓ | L1 |
| `#### xxx` | 1.1.1 | 12pt | ✓ | L2 |
| `##### xxx` | 1.1.1.1 | 12pt | ✓ | L3 |
| `###### xxx` | （1） | 12pt | ✓ | L4 |
| 正文 | — | 12pt(小四) | — | — |

- 字体：全部宋体/Times New Roman，黑色
- 正文：首行缩进2字符(24pt)，1.5倍行距，两端对齐
- 标题：左对齐，无缩进，所有标题加粗
- 最小标题字号12pt（小四）

### 插图

```markdown
![架构示意图](path/to/diagram.png)
```

- 图表优先使用 draw.io 格式（`.drawio`），转PNG后嵌入
- 转换器自动嵌入图片并在下方生成加粗标题：`图1：架构示意图`
- **draw.io 换行规则**：value 属性中用 `&#xa;` 换行，不能出现 `&lt;br&gt;`
- 如果图片缺失，不要编造，告知用户补充

## 公文格式（GB/T 9704-2012）

### 工作流

```bash
python3 ${SKILL_DIR}/scripts/md_to_official.py input.md output.docx
python3 ${SKILL_DIR}/scripts/validate_official.py output.docx
```

### 格式规范

| 元素 | 中文字体 | 字号 | 加粗 | 对齐 | 行距 |
|------|---------|------|------|------|------|
| 标题 | 方正小标宋_GBK | 二号22pt | — | 居中 | 固定34pt |
| 一级标题(一、) | 方正黑体_GBK | 三号16pt | — | 两端 | 固定29pt |
| 二级标题(（一）) | 方正楷体_GBK | 三号16pt | — | 两端 | 固定29pt |
| 三级标题(1.) | 方正仿宋_GBK | 三号16pt | ✓ | 两端 | 固定29pt |
| 正文 | 方正仿宋_GBK | 三号16pt | — | 两端 | 固定29pt |

- 页边距：上3.7cm 下3.5cm 左2.8cm 右2.6cm
- 西文字体：Times New Roman
- 正文首行缩进2字符(32pt)
- 页码：页面底端居中，Times New Roman 4号14pt

## Markdown 书写规则

仅使用以下结构：

```markdown
# 文档标题
## 一级标题（脚本自动生成"一、"）
### 二级标题（脚本自动生成"1.1"）
#### 三级标题
##### 四级标题
###### 五级标题（普通模式）
正文段落
![图题](path/to/image.png)
```

- 不要手动添加标题序号（脚本自动编号，保证一致性）
- 每个段落写成一行
- 避免表格、HTML、脚注、嵌套列表、装饰符号和emoji
- 不要写入 Word 格式指令

---

## 可靠性护栏

1. 必须运行验证器，验证不通过不能声称完成
2. 注意字体提示：即使 DOCX 声明了正确字体，如果系统未安装对应字体，Word 会替代显示
3. 如果源文本混乱，先整理成规范的 Markdown 结构

---

## 交付检查清单

生成完成后报告：
- 确认的模式（普通/公文）
- 输出 `.docx` 路径
- 验证结果
- 是否自动编号
- 缺失的图片文件
- 字体安装提示（如相关）

## 脚本说明

| 脚本 | 用途 |
|------|------|
| `md_to_normal.py` | Markdown → 普通格式 DOCX（自动编号） |
| `md_to_official.py` | Markdown → 公文格式 DOCX（自动编号） |
| `validate_normal.py` | 普通格式逐段校验 |
| `validate_official.py` | 公文格式逐段校验 |
| `build_docx.py` | python-docx 手写模板（fallback，不常用） |
